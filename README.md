# Eval Studio

在本地运行的 Agent 评测工具：导入案例、调用 Agent、模型评分、复核 Bad Case、记录归因并导出报告。

## 快速开始

安装 Node.js 24 或更新版本，然后在项目目录执行：

```sh
npm ci
npm start
```

打开 http://127.0.0.1:4189 。账号为 `admin`，首次随机生成的密码见 `.data/initial-admin-password.txt`，登录后必须修改密码。

## 使用流程

1. **准备数据**：上传 CSV / XLSX / XLS，或手动录入案例。可导入 50 条销售合成示例。
2. **配置被测 Agent**：填写自己的 API 地址、鉴权信息、请求字段映射及回答提取路径。
3. **配置评分模型和标准**：填写自己的 OpenAI 兼容模型接口、模型名称和 API Key，设置评分提示词、维度和通过门槛。
4. **先试跑一条**：核对 Agent 收到的输入、返回的回答和评分结果。
5. **批量评测**：并行数可设 1–50，默认 3；实际需符合 API 的限流要求。共享会话时按顺序运行。
6. **复核与归因**：查看不通过案例的输入、回答和评分证据，人工确认问题及原因。
7. **导出结果**：保存报告或数据，供复盘和后续版本对比。

也可以上传已有 Agent 回答，仅调用评分模型，不再调用 Agent。

## API 与提示词

本项目不附带可用的 Agent 服务、模型额度或 API Key。被测 Agent 与评分模型是两套独立配置，费用由使用者自己的服务产生。

Agent 支持可配置的 HTTP 请求、Header、JSON 请求体、字段绑定和回答提取，以及 JSON、纯文本、SSE、NDJSON 响应。复杂的异步接口或平台专有协议可能需要额外适配。

Agent 配置页的系统提示词、用户提示词需要通过请求模板传入接口，才会生效；Agent 服务内部的提示词仍由该服务管理。评分提示词与评分规则在本工具中独立配置。

## 数据字段

| 字段 | 用途 |
| --- | --- |
| case_id | 案例编号 |
| user_input | 用户输入 |
| context | 本例上下文、知识库资料 |
| criteria | 应做到与不得发生的行为 |
| category / difficulty | 分类与难度 |
| instruction | 本例任务要求 |
| agent_answer | 已有回答（可通过字段映射指定） |

示例数据均为合成场景，难例不代表 Agent 一定会失败，必须根据实际回答判定。示例包含业务专用的 `case_json` 扩展，使用者可按自己的接口映射字段。

## 本地存储与运行

数据、API 配置和登录信息保存在 `.data`，不应提交到 GitHub。业务数据库加密保存，备份时需同时保留数据库与加密密钥，并妥善保管整个目录。不要公开自己的运行记录或密钥。

默认仅监听本机，当前版本面向本地使用，不是多租户云服务；不能仅通过 GitHub Pages 运行后端。

可通过环境变量设置 `EVAL_PORT`（默认 4189）和 `EVAL_DATA_DIR`（数据目录）。关闭终端服务即停止；中断的任务需在重启后检查并恢复。
